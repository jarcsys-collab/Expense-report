# ReceiptFlow staging

A complete copy of ReceiptFlow that shares nothing writable with production.

| | Production | Staging |
| --- | --- | --- |
| Frontend | GitHub Pages, `jarcsys-collab.github.io` | Cloudflare Pages, direct upload |
| API | Railway project `expense-report` | Separate Railway project `receiptflow-staging`, service `receiptflow-staging-api` |
| Database | Production Atlas cluster | Separate Atlas project and free cluster, database `receiptflow-staging` |
| Microsoft sign-in | Existing app registration | Separate `ReceiptFlow Staging` app registration, same tenant |
| OCR | Google Document AI | Stub: nothing is sent to Google |
| Entry point | `npm start` | `node scripts/staging-server.js` |
| Approval, notifications, cleanup | As configured | Forced off |

**Why not a second GitHub Pages site?** A repository has one Pages site, so it would overwrite production. A second
repository's site would have the same origin, `jarcsys-collab.github.io`, so staging and production could not be told
apart for CORS or browser storage.

## Automatic safeguards

`server/scripts/staging-server.js` refuses to start unless all of these hold:

- `NODE_ENV` is `production`, and the database is named as staging and is not `receiptflow`.
- Notifications, approval routing, receipt cleanup, beta sign-in and development sign-in are all off.
- `FRONTEND_ORIGIN` is an https address that is not the production frontend.
- The Entra client is not production's.
- The database user **cannot read** a database named `receiptflow`. Only "not authorized" is accepted.

It also removes the production frontend from the allowed origins, which the normal server always includes.

`npm run build:staging` refuses production's API, app registration or address, and writes only to `dist-staging/`.

**Caution:** this folder's Railway CLI is linked to a different project (`jarc-database`). Do not run `railway up` from
here unless you have run `railway link` to the staging project first and confirmed it with `railway status`.

## Setup

Order matters: each step produces a value the next one needs.

### 1. Database (MongoDB Atlas, free)

At <https://cloud.mongodb.com>:

1. Project selector > **New Project**, name `receiptflow-staging`.
2. **Create** a cluster, choose **Free (M0)**, name `receiptflow-staging`.
3. **Security > Database & Network Access > Database Users > Add New Database User**. Password authentication, username
   `receiptflow-staging-app`, an autogenerated password. Under **Database User Privileges > Add Specific Privilege**,
   choose `readWrite` on database `receiptflow-staging`. No other privileges.
4. **Network Access > Add IP Address**. Railway's addresses change unless you have static IPs, so this is usually
   `0.0.0.0/0`. The password and the limited user are then what protect the database, which holds only synthetic data.
5. **Connect > Drivers**, copy the connection string, and keep it only for step 3.

Do not copy any production data. Records appear as people sign in and scan the synthetic receipt.

### 2. Sign-in (Microsoft Entra admin center, free)

Do this after step 4 gives you the frontend address, then come back to fill in the IDs.

At <https://entra.microsoft.com>, **Identity > Applications > App registrations > New registration**:

1. Name `ReceiptFlow Staging`. Accounts in this organizational directory only.
2. Redirect URI: platform **Single-page application (SPA)**, value `https://<staging-frontend-host>/`, with the trailing slash.
3. **API permissions**: confirm Microsoft Graph, delegated, `User.Read`.
4. Copy the **Application (client) ID** and **Directory (tenant) ID**. They are public identifiers.

Production's app registration is not changed. Tokens issued for one are rejected by the other.

### 3. API (Railway; usage-billed, needs your approval)

At <https://railway.com/dashboard>:

1. **New Project > Deploy from GitHub repo**, `jarcsys-collab/Expense-report`. Name the project `receiptflow-staging`
   and the service `receiptflow-staging-api`. It must be a new project, not a service in `expense-report`.
2. Service **Settings**:
   - **Source > Root Directory**: `/server`
   - **Source > Branch**: `feature/receiptflow-2-staging`
   - **Config-as-code > Railway Config File**: `/server/railway.staging.json`
   - **Networking > Generate Domain**
3. **Variables**: the list in `server/.env.staging.example`. Mark `MONGODB_URI` as sealed. Set no Google variables.
4. Deploy once the checks below pass, then read the logs. They must contain
   `[staging] STAGING service. OCR: STUB`. If that line is missing, the service is not using the staging entry point:
   remove the deployment and check the config file setting.

A Railway service follows one branch, so it deploys only from that branch, and production does not follow it.

### 4. Frontend (Cloudflare Pages, free)

Direct upload has no connection to the repository, so a push can never publish it.

1. At <https://dash.cloudflare.com>, **Workers & Pages > Create > Pages > Upload assets**, project name
   `receiptflow-staging`. Note the address, `https://receiptflow-staging.pages.dev` if the name is free.
2. Locally: copy `.env.staging.example` to `.env.staging.local`, fill it in, and run `npm run build:staging`.
3. Upload the `dist-staging` folder as the project's deployment.

## Checks before the first deployment

- [ ] Atlas project is new; the production project is untouched.
- [ ] The database user has only `readWrite@receiptflow-staging`.
- [ ] The Railway project is new and its branch is `feature/receiptflow-2-staging`.
- [ ] The config file is `/server/railway.staging.json`.
- [ ] No production variable was copied: no production `MONGODB_URI`, no Google key.
- [ ] `FRONTEND_ORIGIN` and the Entra IDs are the staging ones.
- [ ] `git log` shows the feature branch has not been merged into `main`.

## Later: a controlled real-OCR test

Needs separate written approval, because it is billable (about US$0.10 per page group at list price).

1. In a **separate Google Cloud project**, enable Document AI, create an Expense Parser processor and a service account
   with only the Document AI API User role. Set a budget alert. Do not reuse production's key.
2. In Railway, set `STAGING_OCR_MODE=real`, `OCR_PROVIDER=google_document_ai`, the three `GOOGLE_DOCUMENT_AI_*` identifiers
   and `GOOGLE_DOCUMENT_AI_CREDENTIALS_JSON` as a sealed variable.
3. Scan the agreed number of synthetic or consented receipts, compare with the Google Cloud billing report, then set the
   mode back to `stub` and delete the key.
